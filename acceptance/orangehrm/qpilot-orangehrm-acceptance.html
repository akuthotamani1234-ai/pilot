Qpilot on OrangeHRM: what really happened

Target: opensource-demo.orangehrmlive.com Date: 21 Nov 2026 Branch tested: final @ 71ae91f Code changed: none

The short answer

Is it real? Yes. We started Qpilot, typed the OrangeHRM address and the demo login into its dashboard, and clicked Explore and test website. A real Chrome browser opened the real website, logged in, visited 25 pages in 12 different modules, and ran 295 tests with 1,101 checks. Four browsers worked at the same time. Every number on this page comes from files Qpilot saved during the run.

Is it 100%? No, and Qpilot says so itself. It stopped at the 25-page limit we set (41 more pages were found but not opened), it did not press buttons that change data, and it gave the run the honest verdict Insufficient Evidence. Six of the seven requirements passed. One passed only partly: browser recordings (traces) are not saved with the default settings. With one setting changed, a third run saved 44 of them.

Two different meanings of “100%”

100% real execution

Every action shown is something a real browser did, with a screenshot or log to prove it.

Shown in this test

100% feature coverage

Every page and every button of the website is tested. No tool can promise this for any website: some parts need permissions, test data, or actions that change real records.

Not promised. Gaps are listed.

What the 60 failures really are

A failed test does not always mean the website is broken. Qpilot sorted every failure, and we checked its sorting.

30
Our test machine, not OrangeHRM.The “every link works” check could not find the site's address (ENOTFOUND). Our cloud machine only reaches websites through a proxy, and this check doesn't go through it. Qpilot labelled these “infrastructure”, which is correct. On a normal PC they should run.
20
Real website findings.At phone width (390 px), OrangeHRM pages scroll sideways or controls are cut off. Seen on 24 pages.
24
Weak spots in Qpilot's own tests.18 tests could not target exactly one element (“locator”), and 6 were faulty tests. Qpilot listed these as its own problems, not as website bugs. They should be fixed in Qpilot.

Qpilot's analysis lists 88 findings in total, because some tests produce more than one finding and inconclusive results are counted too.

What was not tested, and why

  • 41 more pages. We set a 25-page limit to keep the run short. Choose “All discovered pages” to go further.
  • Buttons that change data (Save, Approve, Assign Leave, Post…). These stay blocked unless you choose a staging environment and allow writes. This protects shared and real systems.
  • The help site (starterhelp.orangehrm.com). It is a different website, so leaving it out is correct.
  • AI planning. No AI service was connected (no Ollama and no API key), so we ran in “Rules only” mode. The 4 workers are real parallel browsers running rule-made tests. The AI part of “AI agents” was not part of this test.

What should be fixed before approval

  1. Save traces by default. Today a trace is recorded only when a failed test runs again, and repeats are off by default (TEST_RETRIES=0). Either set it to 1 by default, or record traces on the first try.
  2. Make the link check use the system proxy, so it works on company networks and cloud machines too.
  3. Fix the 24 weak tests (18 that could not target one element, 6 faulty tests) so failures point only at the website.
  4. Repeat with an AI service connected to prove the AI part of the agents.

How we ran it (so anyone can repeat it)

  1. Started the Qpilot server: python -m backend.server, which serves the dashboard at http://127.0.0.1:8000.
  2. In the dashboard: Web testing → Standard testing → pasted the OrangeHRM URL → Configure test.
  3. Chose “Use my existing test account” and typed the public demo login that OrangeHRM shows on its own login page.
  4. Chose “Rules only”, “Standard” intensity and a 25-page limit. Ticked “I am authorized”. Turned off Watch mode, because our machine has no screen; this gives the parallel hidden browsers.
  5. Clicked Explore and test website and saved a screenshot of the dashboard every 30 seconds.

One setup fix was needed on our side only. Our cloud machine had a different Chromium build than the one Qpilot's Playwright 1.64 expects. We pointed it at the installed browser; no Qpilot code was changed. The first try without this fix stopped correctly with “0 pages visited, Insufficient Evidence” rather than pretending to work.
