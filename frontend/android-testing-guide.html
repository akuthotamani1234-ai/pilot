METHOD 1 / APK FILE

Give Qpilot the app's installation file

Qpilot installs the APK on your selected Android device.

1

Get the APK from the app owner

For the Sauce Labs demo, open its official GitHub releases.

Open a release → Assets → download the file ending in .apk. Do not choose the source-code ZIP.

2

Keep the file on your Windows computer

Downloads is fine. No special project folder is required.

A demo APK already exists in your Blow Ai project:

runs\sauce_appium_verification\mda-2.3.0-27.apk
3

Choose the file in Qpilot

ANDROID TESTING → STANDARD TESTING

APK on your PC→Qpilot / Appium→Install + launch on Android
The emulator and Appium must already be running. APK upload alone does not configure login credentials or prove whole-app coverage.

METHOD 2 / INSTALLED APP

Give Qpilot the app's package name

The app must already be installed on the selected Android device.

1

Install the app on the emulator first

You can keep the app installed after Method 1.

Or drag the downloaded APK from Windows onto the running emulator to install it.

Open the app manually once to confirm it launches.

2

Find its Android package name

Ask the app developer, or inspect the installed package with Android tools.

The Sauce Labs demo's package name is:

com.saucelabs.mydemoapp.android

This is an app identifier, not the APK filename or its Windows path.

3

Enter the package in Qpilot

ANDROID TESTING → STANDARD TESTING
App source
Already installed on the device ▾
Android device
The same device where the app is installed
Installed app package name
com.saucelabs.mydemoapp.android
Launch activity (optional)
Leave blank for automatic launcher detection
Tick permission → Start Android test
Installed app+Package name→Appium launches + tests
No APK upload is needed for this method. Installing the app on a different emulator does not make it available on the selected device.

METHOD 3 / ANDROID CHROME

Give Qpilot a website URL

Similar to your web workflow, but Chrome runs inside Android.

1

Prepare Chrome on the Android device

Open Chrome inside the emulator or phone.

Finish first-use prompts and confirm a website loads.

Chrome must be installed, and the Android device needs network access.

2

Choose a demo website

For a login demonstration, use:

https://the-internet.herokuapp.com/login

For other examples, visit the-internet.herokuapp.com and choose dropdowns, checkboxes or another page.

3

Enter the URL in Qpilot

ANDROID TESTING → STANDARD TESTING
App source
Website in Android Chrome ▾
Android device
Your emulator or phone with Chrome installed
Website URL
https://the-internet.herokuapp.com/login
Tick permission → Start Android test
Website URL→Appium + Chrome→Website on Android
No application APK or package name is needed. To test successful login or form submission, configure approved flows, test data and expected results.
All three methods: start device + Appium → select source → configure checks → start → review evidence.
ACCURACY PLAYBOOK

Explore reachable screens and verify outcomes

Default Android exploration continues through eligible controls until exhausted. Stop, time limits and protected-action rules still apply.

1

Day-to-day = Test studio

Accuracy Lab only scores whether Qpilot matched known truths. It does not test your app.

2

Add a test login when the app has auth

Without credentials, login-walled screens stay unreachable.

3

Use approved QA contracts for must-pass flows

Login, cart, and critical screens need expected results — not only “button exists”.

4

Leave soft caps at 0 for until-exhausted

Optional numbers in Advanced are soft caps. 0 means keep going until the frontier is empty. Tick test-build mode to exercise forms and cart actions.

5

Read blocked actions and remaining gaps

Each protected or unfinished scenario needs a reason. No whole-app accuracy percentage is claimed.

Checkout, payment, destructive actions and external device features retain their safeguards. Review the coverage panel for exact reasons.
Exhaustive exploration + credentials + contracts — not a fake 100% claim.
