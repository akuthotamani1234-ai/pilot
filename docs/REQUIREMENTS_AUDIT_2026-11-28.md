## Root causes and fixes

### OpenAI 429 during test design

The reproduced path was Studio Execution Center → `POST /api/requirements/executions` → `requirements_api.start_execution` → `bridge.plan` → the existing engine job → `test_design.my_test_cases` → `llm.ask_structured` → `llm.ask_llm` → `_ask_once` → OpenAI Chat Completions. The baseline client treated every 429 as retryable, ignored `Retry-After`, and reused provider response text in the exception. The design stage converted the exception into a generic Not Automated result, and the bridge lacked a structured stop cause in the engine summary.

The wrapper now inspects structured provider error fields. Exhausted credits, spend limits and quota stop immediately. Retryable failures use jitter and a bounded delay, including the server's minimum delay when available. A delay outside the retry budget returns a block. Cancellation is checked while waiting for a request slot and during backoff. The existing socket timeout bounds an in-flight HTTP request. `LLM_MAX_IN_FLIGHT` controls per-provider capacity within one Qpilot process. Only allowlisted diagnostics are recorded for 429/503. The offline request ID `req_fixture_recovered` belongs to the recovery test. The test-design event records its batch size of 24 and sanitized rate headers. Token counts on rejected requests are recorded as unknown, and successful token counts continue through the cost recorder. No provider is switched. [OpenAI error codes](https://developers.openai.com/api/docs/guides/error-codes) · [OpenAI rate limits](https://developers.openai.com/api/docs/guides/rate-limits)

Changed locations include [provider classification and retry](../backend/llm/__init__.py#L126), [design](../backend/agents/test_design.py#L1744), [run stop and summary](../main.py#L145), [report JSON](../backend/agents/reporter.py#L1527), [result collection](../backend/atlassian/bridge.py#L546), and [execution settlement](../backend/requirements_api.py#L491). The existing `GET /api/requirements/executions/{id}` adds `provider_failure` to affected runs and `blocked_by_provider` to affected case results. Unexecuted cases do not increase failure or execution counts. An interrupted batch waits for explicit resume. A single run can be retried with the affected saved case IDs from Reports. Batched resume restarts the interrupted batch, including its prerequisites.

### Ordered test design and resume

The shared structured-response validator previously removed invalid entries from a list. Test design then assigned the shortened list to approved cases by position. An invalid entry could therefore move a valid later plan to the wrong requirement. Ordered design batches now require the expected count and preserve invalid positions, so an invalid entry cannot silently shift its neighboring plan.

An interrupted execution also stopped the Live Execution polling timer. The Resume action now refreshes the execution immediately and accepts a replacement provider key in a password field. The key is submitted transiently and cleared from the form. The Chromium test checks that a resumed batch returns to Running. [Design and reuse tests](../artifacts/requirements-audit/design-regression.log) · [Provider UI tests](../artifacts/requirements-audit/final-provider-ui.log)

### Navbar and missing execution activity

The older checkout predated the backend's distinction between saved tokens and verified connections and predated Studio's job ownership checks. Upstream `b722387` and `040e2ff` supply those changes. [Workflow stage computation](../backend/atlassian/workflow.py#L115) reads independent evidence for connection, import, analysis, review, generation, execution and report. Local browser verification covered the connection color and the next stage remaining pending. Two remaining issues were identified in [workflow computation](../backend/atlassian/workflow.py#L115) and the [workflow API](../backend/requirements_api.py#L1753). The latest import was tenant-wide and previously imported rows took precedence over a newer failed or partial import. The active draft now scopes the stepper to its connection and project. A scope switch clears the prior case selection, execution and target from the draft while preserving historical records. Partial and failed imports keep their own colors and persisted results are consulted when the in-memory job is gone.

The integration and import panels could also be routed twice when an early hash change raced initialization. Both views could redraw the form while it was being filled. Studio now renders the selected view after startup finishes and processes subsequent navigation normally.

The project listing and import paths also looked up the token after Atlassian replied. A rotation in that window could bind a successful response to the replacement token. [The connector](../backend/requirements_api.py#L122) now binds those calls and the verification fingerprint to the same credential snapshot. The regression test rotates the token during the project request and observes an unverified replacement.

The recorded symptom alone cannot establish whether a browser ever started in the original run. At the current revision the browser panel consumes only saved worker frames, the Agents panel consumes registered agent snapshots, and the activity log consumes persisted events through [run events](../backend/server.py#L4196). A provider wait did not emit its own test-design event. The shared live event format now records actual provider retries and blocks. [Live Execution](../frontend/requirements.js#L1891) uses the terminal reason when the expected frame, agent list or event list is empty. No browser or agent evidence is synthesized.

### Duplicate issue keys across connections

[Source storage](../backend/atlassian/store.py#L35) distinguishes connections, while analysis is keyed by tenant and the external Jira issue key or Confluence page ID. Two sites can supply the same ID. Item reads, reviews and generation now verify the rooted source before serving an analysis. Analysis refuses to inherit a different connection's decisions and the store's conditional upsert protects the same identity boundary. The guard preserves existing IDs and schema. A full connection-scoped identifier migration is still required to analyze both colliding items in one tenant.

## Regression

The final local code snapshot passed the complete regression suite on pinned Python 3.13.15 in 49 minutes and 22 seconds. The suite recorded **2,748 passed, zero failures, and 41 skipped**. This run used a regular isolated clone without the workspace `.env`, a canonical temporary directory, and four pytest workers. It passed the previously failing DemoStore accuracy benchmark. Live QPL, Confluence Cloud and paid-provider acceptance remain blocked on authorized access. ## Delivery status

The changes use the existing endpoints and SQLite schema. Requirements Explorer adds an optional `project` filter to the items endpoint. They extend run summary, live events and execution JSON. The list of modified files is available through `git diff --name-only`. This audit requires a read-enabled QPL tenant, a Confluence space with pages linked to the selected requirements, an authorized funded OpenAI project for `gpt-4o-mini`, and the original recording or sanitized provider response to classify the reported incident. Device acceptance also needs a compatible device or emulator and an authorized app. ADB returned no devices and `simctl` was unavailable. iOS preflight now detects an installed `xcrun` shim whose simulator tools are unavailable. Live Jira write-back requires separate approval.
