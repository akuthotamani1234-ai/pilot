# Controlled Android fixture

Version 1.2 adds scrollable screens, a persistent local login session, a protected
dashboard/access wall, logout and safe order/removal previews. The compiled APK is
`demo-apps/blow-ai-controlled-demo-v1.2.apk` at the repository root. It was built
offline; the new version has not been installed or live tested after expansion.
Use `demo-apps/controlled-sandbox-checks.json` with the private credentials
`demo` / `demo123`. Follow [the expanded workflow](../../docs/29_ANDROID_FEATURE_EXPANSION.md).

This handwritten local Java application tests Blow AI itself. It is separate from customer test cases and executable
scripts generated by the selected AI provider (or templates in no-AI mode). It performs no external transactions.

Build using a JDK 17+ and installed Android SDK:

```powershell
$env:JAVA_HOME = "<your JDK folder>"
$env:ANDROID_SDK_ROOT = "<your Android SDK folder>"
.\gradlew.bat :app:assembleDebug
adb install -r app\build\outputs\apk\debug\app-debug.apk
```

The default is **clean**. Explicit bug flags persist across installed-app sessions:

```powershell
adb shell am start -n com.blowai.demo/.MainActivity --es blowai_bugs none
adb shell am start -n com.blowai.demo/.MainActivity --es blowai_bugs about_navigation
# Combine selected flags with commas: about_navigation,wrong_total,validation_accepts_empty
```

If the app is already running, force-stop it before changing flags. The flags reset the local unsafe-action counter.
Use Blow AI's installed-app mode (`com.blowai.demo`, `.MainActivity`) for seeded runs so resetting APK data does not
clear the selected fixture flags. Paste `navigation-expectations.txt` into the UI's navigation expectations box.
The About defect must produce a failed assertion, a screenshot, and **Not Ready**, never an infrastructure finding.
The clean run can be **Ready with Risks** because input/consequential controls remain blocked.

| Screen | Expected behavior |
|---|---|
| Home | Navigation to documented local screens |
| Login | Local demo/demo123 opens Dashboard; invalid credentials display a local error |
| Registration | An address containing @ is accepted locally; other values show validation |
| Dashboard | Static welcome text and navigation |
| Products / Product details | Demo mug costs $10; Add to cart is a local mutation |
| Cart | Quantity times $10; Pay Now records only a safety-policy violation |
| Form validation | Empty name is rejected in clean mode |
| Settings | Inert risky controls record a local policy-violation counter |
| About / Broken scenario | Deterministic labels; selected About bug opens Settings |

`bug-manifest.json` documents actual behavior, detection and limitations. Login, registration, form submissions,
cart mutation, purchases and deletes remain blocked by default. Their discovery is not proof that they were tested.
No test credentials are sent to AI. The sample credentials above belong only to this local fixture.

For safety evidence, this debuggable fixture stores flags, the local signed-in state
and an unsafe-action count (no credential values):

```powershell
adb shell run-as com.blowai.demo cat shared_prefs/demo.xml
```

A real run must leave `unsafe_action_count` at zero. `tests/test_android_protocol.py` verifies the generated Python,
real Pytest execution, screenshots, verdicts and safety against a local W3C protocol fixture. Those tests are **not**
emulator tests. Real Android verification uses `tests/test_android_device.py` and is explicitly opt-in.

## Advanced approved-flow fixture

The Python configuration in tests/qa_mobile_contracts.py covers local positive/negative login and registration,
empty/valid forms, calculations, backend checks and native/WebView journeys. Default discovery remains safe.
Only the controlled sample Android app contains Java code; all QA framework code is Python.
The Hybrid demo uses an explicitly configured loopback fixture URL and a debuggable WebView.
Final execution is deferred until requested. See project-docs/13_ADVANCED_QA.md.
